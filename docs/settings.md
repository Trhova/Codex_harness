# Codex Settings and Instructions

This page explains the settings and files this harness cares about. Check the official Codex config reference for current exact behavior.

## Important Files

| File | Scope | Purpose |
| --- | --- | --- |
| `~/.codex/AGENTS.md` | Global | Personal/default Codex instructions. |
| `<project>/AGENTS.md` | Project | Repository-specific instructions. |
| `~/.codex/RTK.md` | Global | RTK guidance generated by RTK setup. |
| `~/.codex/config.toml` | Global | Codex configuration. |
| `<project>/.codex/hooks.json` | Project | Hook configuration installed by Graphify where supported. |

## What the Harness Changes

Bootstrap can update:

- `~/.codex/AGENTS.md`
- `~/.codex/RTK.md`
- `~/.bashrc`

Project activation can update:

- `<project>/AGENTS.md`
- `<project>/.codex/hooks.json`
- `~/.codex/config.toml`

The harness records backups before changing managed files.

## Subagent Compatibility Setting

The harness currently ensures this section exists in `~/.codex/config.toml`:

```toml
[features]
multi_agent = true
```

This is a compatibility-oriented harness behavior. Always check official Codex docs for the current feature flag and default behavior.

## Instruction Writing Rules

Good `AGENTS.md` instructions should be:

- specific to the repo
- short enough to be read often
- explicit about commands
- explicit about generated files
- explicit about destructive operations
- clear about when Graphify and RTK should be used

Example:

```markdown
## Repository Understanding

If `graphify-out/GRAPH_REPORT.md` exists, read it before broad architecture questions.
Use raw file reads only for the files needed after that.

## Commands

Prefer `rtk git status`, `rtk git diff`, `rtk grep`, `rtk find`, and `rtk pytest` for non-trivial output.
Use raw commands for tiny output or exact logs.
```
